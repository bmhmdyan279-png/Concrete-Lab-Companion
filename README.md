**نسخه ۴.۰.۰ – معماری موتور محاسباتی جدا از نمایش**

نسخه ۴ محصول را از «اسکریپت تولید اکسل» به یک **سیستم محاسباتی/QA مدل‌محور** ارتقا می‌دهد:
علم آزمایش‌ها در پایتون محاسبه و با موارد طلایی راستی‌آزمایی می‌شود؛ اکسل فقط **نمایش** نتایج است —
بدون حتی یک فرمول محاسباتی در فایل.

---

## 🏛 معماری نسخه ۴

```
standards DB (rulesets) → domain engine → validation/QA → Excel renderer (display-only)
```

| لایه          | مسیر                             | مسئولیت                                                                            |
| ------------- | -------------------------------- | ---------------------------------------------------------------------------------- |
| دامنه         | `src/concrete_lab/domain/`       | اشیای مقدار (`Quantity`, `ValidationStatus`, …) و موتور محاسبه                     |
| استانداردها   | `src/concrete_lab/standards/`    | رولسیت‌های تایپ‌شده: `C39-26`, `C805-25`, `ISIRI 302 (1394)` + رجیستری حسابرسی‌شده |
| مشخصات آزمایش | `src/concrete_lab/specs/`        | کاتالوگ داده‌محور ۲۰ آزمایش (ثبت غیرمتمرکز، فصل‌به‌فصل)                            |
| QA            | `src/concrete_lab/qa/`           | اجرای واقعی pytest، سوئیت طلایی درون‌فرآیندی، بررسی ساختاری محصول                  |
| نمایش         | `src/concrete_lab/render/excel/` | رندر فقط‌نمایشی: مدل داده → شیت (بدون منطق)                                        |
| گزارش         | `src/concrete_lab/report/`       | Manifest با ردیابی کامل (نسخه‌ها، قوانین، QA، SHA-256)                             |
| ارکستراتور    | `build.py`                       | فایل کوچک ورودی؛ فقط راه‌اندازی و واگذاری به CLI                                   |

### مرز استاندارد و تخمین

- **ASTM C39/C39M-26**: فقط استوانه؛ هندسه مکعب با خطای صریح «خارج از دامنه» رد می‌شود (هرگز ضریب تجربی خودکار). اصلاح L/D با جدول منتشرشده و **درون‌یابی خطی**.
- **ASTM C805/C805M-25**: `scope=ESTIMATION` با بج «ESTIMATED — NOT FOR ACCEPTANCE» و سلب مسئولیت قوی دوزبانه؛ هیچ فرمول جهانی عدد بازگشت→مقاومت وجود ندارد و تخمین فقط با همبستگی اختصاصی پروژه ممکن است.
- **ISIRI 302 (ویرایش سوم، ۱۳۹۴)**: رولسیت کامل (پاکت دانه‌بندی + باند هشدار نزدیک مرز + قوانین فیزیکی منحنی) به‌جای دیکشنری ساده.

## 🚀 نحوه استفاده

```bash
pip install -r requirements.txt

# ساخت محصول: محاسبه با موتور + رندر + QA ساختاری + manifest
python build.py --output output --no-protect

# اجرای واقعی QA (سوئیت طلایی + pytest) — خروجی غیرصفر در صورت شکست
python build.py --validate

# محدودکردن اعتبارسنجی به بخشی از تست‌ها
python build.py --validate tests/test_domain.py
```

هر ساخت سه سطح QA تولید می‌کند:

| سطح          | شرح                                                | کجا گزارش می‌شود            |
| ------------ | -------------------------------------------------- | --------------------------- |
| golden-suite | اجرای موارد طلایی مقابل موتور (درون‌فرآیندی)       | شیت `24_QA_Test` + manifest |
| structural   | تمامیت فایل، SHA-256، manifest، تضمین «بدون فرمول» | manifest                    |
| pytest-suite | کل سوئیت تست (با `--validate`)                     | خروجی خط فرمان              |

### حفاظت شیت‌ها

رمز از متغیر محیطی `WORKBOOK_PASSWORD` (یا `--password-env`) خوانده می‌شود؛ وضعیت
`Protection: ENABLED/DISABLED` صریح لاگ می‌شود.

> حفاظت شیت فقط جلوی ویرایش تصادفی را می‌گیرد؛ **یک مرز امنیتی نیست.**

## 🛠 توسعه و ساخت مجدد

```bash
python3 -m pytest                # ۲۱۵ تست: دامنه، استانداردها، موتور، QA، رندر، CLI
python3 build.py                 # ساخت با QA تعبیه‌شده
```

اصول حاکم بر کد نسخه ۴:

- **منطق علمی فقط در پایتون** — رندر اکسل هیچ فرمولی نمی‌نویسد و تست ساختاری این قرارداد را در هر ساخت راستی‌آزمایی می‌کند.
- **وضعیت‌ها ساختاریافته‌اند** — `ValidationStatus` شش‌حالته؛ نمایش (✅/⚠️/❌) فقط در لایه رندر.
- **ثابت‌های نام‌دار** به‌جای اعداد جادویی (`constants.py`).
- **Docstring و type hints کامل** در همه ماژول‌ها.
- **بدون کد مرده** — داربست‌های خالی حذف شده‌اند.
- **ردیابی**: هر نتیجه به نسخه رولسیت خود (`C39-2026-v1`, …) ارجاع دارد و manifest هویت کامل ساخت را ثبت می‌کند.

ساختار بسته:

```
src/concrete_lab/
├── cli.py              # CLI واقعی: ساخت و --validate
├── config.py           # پیکربندی معتبرسازی‌شده از config.yaml
├── constants.py        # ثابت‌های نام‌دار
├── domain/             # quantities, statuses, results, engine
├── standards/          # base (StandardSpec, Scope), registry, astm/, isiri/
├── specs/              # کاتالوگ ۲۰ آزمایش (۴ فصل)
├── qa/                 # engine (pytest), golden, structural
├── render/excel/       # model, assembler, renderer, styles, protection
└── report/             # manifest
```
